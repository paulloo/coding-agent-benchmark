# 任务：开发遛狗记录管理模块

请在当前项目中开发一个完整的「遛狗记录管理」模块。必须实际修改项目文件并验证结果，不要只输出方案。

## 一、功能范围

用户可以：

- 创建遛狗记录
- 编辑已有记录
- 删除记录（需要二次确认）
- 查看记录详情
- 按日期范围筛选记录
- 按狗狗筛选记录

每条记录包含：

| 字段 | 说明 |
|---|---|
| dogId | 狗狗 ID |
| startTime | 开始时间 |
| endTime | 结束时间 |
| duration | 遛狗时长（分钟） |
| distance | 遛狗距离（公里） |
| notes | 备注 |
| createdAt | 创建时间 |

## 二、数据规则

- 结束时间必须晚于开始时间。
- 遛狗时长必须大于 0，且不能超过 480 分钟。
- 时长必须与起止时间一致，服务端不得无条件信任客户端提交的时长。
- 距离不能为负数，最大不能超过 50 公里。
- 备注最多 500 个字符。
- 用户只能查看和修改自己拥有的狗狗的遛狗记录。
- 删除记录需要二次确认。

## 三、统计功能

增加本周统计卡片，数据必须从真实记录聚合：

- 本周遛狗次数
- 本周累计时长
- 本周累计距离
- 平均每次遛狗时长

## 四、UI 要求

- 现代 SaaS Dashboard 风格，与现有页面保持一致。
- 桌面端和移动端均可使用。
- 加载、空数据、错误三种状态必须有实际实现。
- 表单有清晰的字段级验证提示。
- 删除操作有确认交互。

## 五、工程要求

- 遵循项目现有架构、目录约定和代码风格。
- 使用 Prisma 实现数据持久化，使用迁移或项目已有的 schema 管理方式。
- 使用 Zod 在服务端校验所有外部输入。
- 补充必要的单元测试和集成测试，覆盖权限和边界条件。
- 不要引入不必要的依赖。
- 不允许破坏现有功能和现有测试。

## 六、交付前必须执行

1. 运行项目现有的类型检查。
2. 运行相关测试。
3. 修复你引入的问题。
4. 汇总修改的文件和实现内容。
5. 列出尚未完成的事项和已知限制。

如果发现现有代码与需求冲突，优先遵循现有架构，并在最终报告中说明取舍。
