# 任务：修复遛狗记录日期筛选异常

## 用户反馈

遛狗记录页面存在日期筛选异常。在 Asia/Shanghai 时区下：

1. 选择 2026-11-18 日期。
2. 页面没有显示当天部分已经创建的遛狗记录。
3. 这些记录在数据库中确实存在。
4. 如果修改日期筛选范围，部分记录又会出现。

## 你的工作

调查并修复这个问题。

## 要求

1. 首先复现问题，记录实际观察到的数据和时间值。
2. 检查前端日期处理逻辑。
3. 检查 API 参数传递和序列化格式。
4. 检查后端日期范围查询的构造方式。
5. 检查数据库存储的时间类型和时区语义。
6. 找出真正的根因。
7. 修复问题。不允许通过简单增加或减少 8 小时来掩盖问题。
8. 补充自动化回归测试。

## 特别注意

- 必须考虑 Asia/Shanghai 时区。
- 必须考虑 UTC 时间存储。
- 必须覆盖一天的开始和结束边界（含当天最后一毫秒）。
- 不允许破坏其他日期筛选功能。

## 最终输出

- 问题根因
- 修复方案
- 修改的文件
- 新增的测试
- 测试执行结果

必须实际修改代码并运行测试，不要只给出分析。
